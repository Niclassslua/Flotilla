# Flotilla Design Context

## Users

Flotilla is for developers who run several local coding-agent sessions at once. They move constantly between projects, long-lived terminals, worktrees, diffs, and project instructions. They are keyboard-first, comfortable with dense developer tooling, and need to understand session state at a glance without losing terminal context.

## Brand Personality

Calm, technical, compact, and purposeful. Flotilla should feel like a reliable local command center: dark, low-distraction, information-rich, and quietly confident. It uses a warm orange signal color for primary actions and cool cyan/green status colors for live system state.

## Aesthetic Direction

Match the supplied Xirp application reference closely in interaction structure and visual hierarchy: a dark full-window IDE shell, a slim persistent global bar, dense project and session workspaces, low-contrast panels, hairline dividers, compact controls, and restrained radii. Avoid decorative gradients, oversized marketing typography, floating-card dashboards, and native toolbar chrome that breaks the continuous workspace.

## Design Principles

1. Preserve context: terminals and session state stay mounted while users inspect related project data.
2. One action away: projects, sessions, grid, restore, search, shortcuts, and settings remain globally reachable.
3. Progressive disclosure: advanced Git, files, review, context, and session metadata appear in dedicated panels or overlays.
4. Dense but legible: use compact spacing, clear hierarchy, and muted supporting text without hiding operational detail.
5. Local and trustworthy: expose paths, branches, process state, and destructive consequences plainly; never imply cloud state or account features that do not exist.
6. Accessible by construction: real buttons, keyboard shortcuts, descriptive labels, visible focus, and status meaning that does not rely on color alone.
